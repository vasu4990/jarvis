System Overview

Hybrid Intelligence Architecture

JARVIS combines local processing for speed and privacy with cloud reasoning for complex tasks. The system follows a 5-layer architecture with strict safety boundaries.

Design Principles

  • Privacy First: Sensitive data stays local
  • Fail-Safe: Hardware kill switch for emergencies
  • Modular: Replace any component independently
  • Aligned: Multi-layer safety gates
  • Extensible: Easy to add new tools and capabilities

Layer-by-Layer Breakdown

1

Input Layer

Captures user commands through multiple channels with low latency.

Voice Input (Whisper)

Purpose: Real-time speech-to-text

  • VAD (Voice Activity Detection)
  • Whisper small model (~500MB)
  • Push-to-talk hotkey (Ctrl+Space)
  • ~2-3s latency
File: input/audio_manager.py

Keyboard Hotkeys

Purpose: Global hotkey registration

  • Ctrl+Space: Push-to-talk
  • Ctrl+Shift+K: Emergency kill switch
  • Ctrl+Shift+J: Toggle JARVIS
File: input/hotkey_manager.py

ESP32 Serial Bridge

Purpose: Hardware button integration

  • Wake button detection
  • Hardware kill switch
  • Gesture input (IMU)
  • USB serial @115200 baud
File: mcu_bridge/serial_handler.py
2

Processing Layer

Understands intent, retrieves context, and plans multi-step actions.

NLU Router

Purpose: Intent classification

  • Simple queries → Local LLM
  • Complex tasks → Cloud GPT-4
  • Tool selection based on intent
  • Confidence scoring
File: nlu/intent_classifier.py

Hybrid Planner

Purpose: Multi-step task decomposition

  • Local planner (LLaMA 7B)
  • Cloud planner (GPT-4)
  • Tool chain generation
  • Fallback strategies
File: agent/planner_cloud.py

Memory Retrieval

Purpose: Context-aware responses

  • ChromaDB vector search
  • MiniLM-L6 embeddings
  • SQLite metadata index
  • Semantic similarity ranking
File: memory/vector_store.py
3

Safety Layer

3-tier permission system ensures AI alignment and prevents harmful actions.

Policy Gate

Purpose: Action permission checking

  • GREEN: Auto-approved
  • YELLOW: Requires confirmation
  • RED: Blocked
  • Rule-based + ML-based policies
File: agent/policy_gate.py

Action Evaluator

Purpose: Risk assessment

  • Reversibility check
  • Impact scope analysis
  • Data sensitivity scoring
  • Cost estimation
File: agent/evaluator.py

Audit Logger

Purpose: Compliance & debugging

  • Timestamped action logs
  • User approval records
  • Tool execution traces
  • Anomaly detection
File: utils/audit_logger.py

Example: File Deletion Request

User: "Delete all PDFs in my Downloads"

1. Policy Gate: Checks deletion rules
   → Scope: Multiple files (YELLOW)
   → Confirmation required

2. Action Evaluator: Assesses risk
   → Reversibility: Possible (Recycle Bin)
   → Impact: Medium (potential data loss)
   → Risk Score: 6/10

3. User Prompt: "Delete 47 PDF files?"
   → User: "Yes"

4. Audit Log: Record approval + action
   → Timestamp, file list, user consent

5. Execute: Move files to Recycle Bin
   → Safe deletion with recovery option
4

Execution Layer

Orchestrates tool execution with error handling and retries.

Tool Orchestrator

Purpose: Manage tool execution pipeline

  • Sequential & parallel execution
  • Dependency resolution
  • Error handling & retries
  • Timeout management
File: agent/orchestrator.py

Tool Registry

Purpose: Dynamic tool loading

  • PowerShell tools
  • Web automation (Playwright)

  • File operations
  • Custom tools (plugins)
File: tools/registry.py

Web Automation

Purpose: Browser control

  • Form filling
  • Screenshot capture
  • Data scraping
File: tools/web_playwright.py

Complete Data Flow

Example: "Open Chrome and go to YouTube"

1

Voice Input

User presses Ctrl+Space, speaks command

audio_manager.py → Whisper → "Open Chrome and go to YouTube"
2

NLU Processing

Router classifies intent and extracts entities

intent_classifier.py → Intent: LAUNCH_APP + WEB_NAVIGATE
Entities: {app: "chrome", url: "youtube.com"}
3

Planning

Planner generates tool chain

planner_cloud.py → Plan:
1. launch_app(name="chrome")
2. navigate_to(url="https://youtube.com")
4

Safety Check

Policy gate approves both actions

policy_gate.py → launch_app: GREEN ✓
navigate_to: GREEN ✓
No confirmation needed
5

Execution

Orchestrator runs tools sequentially

orchestrator.py →
1. os_powershell.launch_app("chrome") → Success
2. web_playwright.navigate("youtube.com") → Success
6

Output

Multi-modal feedback to user

TTS: "Opening Chrome and navigating to YouTube"
LED: 🟢 Green (success)
UI: Toast notification

Deployment Architecture

Local Desktop (Recommended)

All components run on Windows 11 PC

Minimum Requirements

  • CPU: AMD Ryzen 7 / Intel i7 (8+ cores)
  • RAM: 16 GB
  • GPU: 4 GB VRAM (for Whisper)
  • Storage: 20 GB free
  • OS: Windows 11 (WSL2 optional)
✅ Advantages
  • Maximum privacy
  • No API costs (except cloud LLM)
  • Low latency
  • Offline capable
⚠️ Limitations
  • High hardware requirements
  • Single-machine only
  • Manual updates

Hybrid Cloud

Heavy processing offloaded to cloud

Architecture

  • Local: Voice input, UI, hardware bridge
  • Cloud: LLM reasoning, TTS generation
  • Edge: Whisper STT (can be cloud)
  • API Costs: ~$20-50/month
✅ Advantages
  • Lower hardware needs
  • Access anywhere
  • Better LLM quality
  • Easy scaling
⚠️ Limitations
  • Privacy concerns
  • Ongoing API costs
  • Internet required
  • Higher latency
